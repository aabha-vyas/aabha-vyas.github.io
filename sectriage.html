SecTriage

in progressan evaluation platform for tool-using agents · Python 3.12 · started October 2026

I'm building a platform that runs AI agents on security code review and, more importantly, measures how well they do it. An agent reads a small codebase, uses tools to search and read files, and reports vulnerabilities with the file and line. A scorer then compares those reports against a known answer key.

I chose security triage because the answers are checkable. A bug is either in the code or it isn't, so I can score the agent instead of judging it by feel.

how it works

the agent

A loop in plain Python with a budget on steps, time and cost, typed contracts for every tool call, and a recorded stop reason for every run. An append-only log captures each step's model output, tool call, result, tokens and cost, so any run can be replayed and compared.

the evaluation

This is where I spent most of my effort. I wrote three test applications with ten planted bugs, including ones that cross files, plus decoy code that looks dangerous but is safe, and one application with no bugs at all to catch false alarms. I locked those files with hashes so I can't quietly tune toward them, and an independent review confirmed the answer key was complete.

next

still in progress

  • A Docker sandbox so the agent can run commands safely, with no network and resource limits.
  • A durable job queue with workers, retries, and replay from the event log, so a crashed run can be recovered and reproduced.

why I built it this way

At CME I work on messaging infrastructure, so I already care about ordering, replay, latency and failure recovery. SecTriage applies those habits to AI workloads: treat measurement as the product, keep held-out data, and be honest about limits.
